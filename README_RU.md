# Ufanet Intercom для Home Assistant

[English](README.md) | **Русский**

Пользовательская интеграция Home Assistant для домофонов Ufanet / «Умный дом», использующая облачные API официального мобильного приложения.

> Это независимая интеграция сообщества. Она не связана с Ufanet и не поддерживается компанией Ufanet.

## Возможности

- Настройка через интерфейс Home Assistant с использованием договора/логина Ufanet и пароля.
- Открытие двери через сущности Home Assistant `button`.
- LIVE-видео с камеры UCAMS и снимки.
- Просмотр видеоархива с диапазонами доступной записи, масштабированием/перемещением таймлайна и метками звонков.
- История звонков, событие `ufanet_intercom_call`, нативные сущности **«Входящий звонок»** и **«Снимок последнего звонка»**, а также device trigger для редактора автоматизаций.
- Выбор способа получения звонков: polling по умолчанию либо экспериментальный FCM с малой задержкой и резервным опросом.
- Временные гостевые ключи и управление принятым совместным доступом.
- Ручной экспорт архива в MP4 через `ffmpeg -c copy` в Home Assistant Media.
- Постоянная медиатека экспортированных роликов с ограничением срока хранения и общего объёма для каждой камеры.
- Опциональное автоматическое сохранение MP4 при новых звонках домофона.
- Options Flow и диагностика Home Assistant с учётом конфиденциальности.
- Единая Lovelace-карточка: `custom:ufanet-intercom-card`.

## Требования

- Home Assistant **2026.8.0 или новее**.
- Сетевой доступ из Home Assistant к `dom.ufanet.ru`, `cloud.ucams.ru` и медиасерверам UCAMS, адреса которых возвращаются API.
- Для экспериментального FCM дополнительно нужен исходящий HTTPS-доступ к endpoint регистрации Google Firebase/GCM и TLS-доступ к `mtalk.google.com:5228`.
- Для экспорта MP4 и извлечения JPEG последнего звонка: доступный в среде Home Assistant `ffmpeg`. В Home Assistant OS/Container он обычно уже присутствует; для Core/venv может потребоваться установка системного пакета.
- Учётная запись/договор Ufanet, у которой уже есть доступ к домофону в официальном приложении.

## Установка

### Вручную

1. Скопируйте каталог `custom_components/ufanet_intercom` в каталог конфигурации Home Assistant:
   `config/custom_components/ufanet_intercom`.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы → Добавить интеграцию**.
4. Найдите **Ufanet Intercom** и укажите тот же договор/логин и пароль, которые используются в официальном приложении.

### Через HACS как пользовательский репозиторий

Репозиторий совместим с HACS и содержит необходимые GitHub metadata для `alphazulu/ufanet-intercom-home-assistant`.

Для установки как пользовательского репозитория HACS:

1. Откройте HACS → **Custom repositories / Пользовательские репозитории**.
2. Добавьте URL этого GitHub-репозитория с категорией **Integration**.
3. Установите **Ufanet Intercom**.
4. Перезапустите Home Assistant и добавьте интеграцию через **Настройки → Устройства и службы**.

## Lovelace-карточка

Добавьте ресурс как JavaScript-модуль:

```text
/ufanet_intercom/ufanet-archive-card.js?v=0.25.4
```

Минимальная конфигурация карточки:

```yaml
type: custom:ufanet-intercom-card
entity: camera.YOUR_UFANET_CAMERA
default_tab: live
```

Карточка содержит четыре вкладки:

- **LIVE** — видео, кнопка открытия двери, последний звонок и переход к записи звонка.
- **АРХИВ** — таймлайн, метки звонков, экспорт MP4 и медиатека экспортированных роликов.
- **ГОСТИ** — приглашения для совместного доступа, принятые гостевые доступы, временные ключи и их отзыв.
- **ДИАГНОСТИКА** — состояние интеграции без раскрытия токенов, polling, состояние UCAMS/архива и автосохранения.

## Настройки

Откройте **Настройки → Устройства и службы → Ufanet Intercom → Настроить**.

Основные параметры включают режим получения звонков, интервал опроса, сколько секунд брать до звонка, длительность/шаг архива, ограничения срока хранения и размера MP4, а также автоматическое сохранение видео звонков. Значения, явно указанные в YAML конкретной карточки, остаются локальными переопределениями там, где это поддерживается.

### Режимы получения звонков

- **`polling` (по умолчанию)** читает `call-history` с выбранным интервалом и не требует дополнительной настройки.
- **`fcm` (экспериментально)** использует локальный headless FCM receiver как быстрый сигнал о звонке. Источником устойчивого события остаётся `call-history`. До подтверждённого MCS-подключения работает обычный настроенный polling, при отключении listener он восстанавливается автоматически, а при исправном FCM остаётся контрольный опрос раз в 300 секунд.

FCM watchdog отличает запуск задач listener от реального подключения, не мешает библиотеке самостоятельно обрабатывать короткие разрывы и пересоздаёт окончательно остановленный или зависший listener с экспоненциальной задержкой. После длительного сбоя Home Assistant создаёт предупреждение Repair и автоматически закрывает его после восстановления. Вкладка диагностики показывает состояние listener и watchdog, резервный polling, переподключения и время соединений без раскрытия push payload или credentials.

### Автоматизации входящего звонка

Для каждого домофона с историей звонков создаётся бинарный сенсор **«Входящий звонок»**. После подтверждения нового звонка через `call-history` он включается на 30 секунд; следующий звонок перезапускает таймер. Сенсор можно использовать на панели и в автоматизациях по состоянию либо выбрать одноимённый device trigger в визуальном редакторе. Оба варианта одинаково работают с polling и FCM.

Сущность **«Снимок последнего звонка»** приватно загружает токенизированный preview Ufanet, копирует его байты в анонимный перематываемый Linux `memfd` и позволяет локальному `ffmpeg` извлечь JPEG на отметке в одну секунду либо первый доступный кадр. Анонимный источник сразу закрывается, в памяти остаётся только JPEG. Постоянная ошибка проверки или декодирования обрабатывается один раз для каждого звонка, а не повторяется при каждом обновлении coordinator. Исходный URL MP4 не помещается в состояние сущности, не попадает в командную строку `ffmpeg`, а исходное видео не записывается в именованный файл.

Сенсор последнего звонка и событие `ufanet_intercom_call` публикуют только признаки `has_preview` / `has_archive`, но не сами временные URL Ufanet. Кнопка **«Снимок звонка»** в карточке открывает кэшированный JPEG через авторизованный image proxy Home Assistant. **Preview-видео** получает свежий временный URL через авторизованный response-сервис только после явного нажатия и не переносит его в сохраняемое Recorder состояние. Полученный от провайдера HTTP preview URL локально преобразуется в HTTPS до любого запроса; HTTP fallback никогда не используется, а приватная загрузка JPEG интеграцией блокирует автоматические redirect. Диагностика показывает факт такого преобразования, фиксированный класс сигнатуры данных, остановку повторов постоянной ошибки, доступность ffmpeg, безопасный код причины, тип ошибки и счётчики извлечения; Repairs учитывает ошибки отдельных звонков и автоматически закрывается после успешного восстановления.

Готовый blueprint уведомления Companion app находится в [incoming_call_notification.yaml](blueprints/automation/ufanet_intercom/incoming_call_notification.yaml). Импортируйте этот GitHub URL через **Настройки → Автоматизации и сцены → Чертежи**, выберите домофон, его сущность снимка и телефон. По умолчанию уведомление ждёт три секунды, пока формируется JPEG; задержку можно изменить. Действие открытия двери намеренно не добавлено.

FCM-значения не распространяются в репозитории. Продвинутый пользователь извлекает их на своём компьютере из своей декомпилированной копии официального Android-приложения:

```bash
python tools/research/fcm_probe_py/extract_firebase_config.py /путь/к/decompiled-app -o firebase_config.json
```

Скопируйте результат в `/config/ufanet_intercom/firebase_config.json`, выберите `fcm` в настройках интеграции и оставьте стандартный относительный путь `ufanet_intercom/firebase_config.json`. Файл должен находиться внутри каталога конфигурации Home Assistant. Интеграция читает JSON, но не сохраняет его значения в ConfigEntry или диагностике.

Extractor принимает каталог после JADX/apktool/декомпиляции (либо соответствующий resources XML с явно указанным package name); сама интеграция не загружает, не хранит и не разбирает APK. Подробности: [FCM API](docs/api/fcm_RU.md) и [инструкция extractor](tools/research/fcm_probe_py/README_RU.md).

## Автоматическое сохранение звонков

По умолчанию отключено. После включения новый звонок экспортируется асинхронно после того, как требуемый интервал после звонка появился в архиве UCAMS. Например:

- до звонка: 15 секунд;
- после звонка: 45 секунд;
- итоговый запрашиваемый ролик: 60 секунд.

UUID звонка хешируется перед использованием для дедупликации в имени локального файла; исходный UUID в имени файла не сохраняется.

## Локальная медиатека

Ручные и автоматические MP4-экспорты сохраняются в каталоге Home Assistant Media `ufanet_intercom/`. Вкладка **АРХИВ** показывает только ролики выбранной камеры и позволяет открывать, скачивать и удалять их.

## Безопасность

- JWT Ufanet и UCAMS хранятся только в runtime-памяти и намеренно не выводятся в диагностике.
- Сгенерированные гостевые ссылки фактически являются временными средствами доступа — относитесь к ним как к временным учётным данным.
- Открытие двери является реальным физическим действием и требует явного нажатия кнопки/подтверждения в пользовательской карточке.
- Скачиваемая диагностика скрывает логин/пароль и не содержит гостевых/медийных URL и точных идентификаторов камеры.
- Для снимка последнего звонка в памяти остаётся только созданный JPEG; preview-видео и его токенизированный URL не сохраняются.
- Токенизированные URL медиа звонков остаются только внутренними runtime-данными и не публикуются в состояниях сущностей или событиях `ufanet_intercom_call`. Явный авторизованный ответ сервиса архива по-прежнему может содержать временный URL, необходимый для воспроизведения.
- Firebase-значения, FCM credentials и локальный путь к Firebase-конфигу не попадают в диагностику. Не коммитьте `firebase_config.json`.

## Диагностика проблем

Перед созданием issue о проблеме упаковки или frontend можно запустить встроенную проверку репозитория:

```bash
python scripts/release_check.py
```

В Home Assistant можно использовать вкладку **ДИАГНОСТИКА** карточки для просмотра текущего рабочего состояния либо **Скачать диагностику** на странице интеграции/устройства для получения обезличенных данных поддержки.

Если локальный `ffmpeg` недоступен или извлечение JPEG последнего звонка завершается ошибкой несколько раз подряд, Home Assistant создаёт Repairs warning. Обнаружение звонков, просмотр архива и управление дверью продолжают работать; после успешного извлечения снимка предупреждение закрывается автоматически.

## Разработка и проверка релиза

`python scripts/release_check.py` проверяет, в частности:

- компиляцию Python и корректность JSON;
- синтаксис JavaScript, если установлен Node.js;
- совпадение версий интеграции, карточки и cache-bust URL;
- вызовы `this._method()` в пользовательской карточке, для которых отсутствует объявление метода;
- имена сервисов, используемых карточкой;
- отсутствие упакованных `__pycache__`, `.pyc`, очевидных JWT и действующих гостевых ссылок.

Инструкции по публикации через HACS/GitHub находятся в [PUBLISHING.md](PUBLISHING.md).
