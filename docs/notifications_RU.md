# Полноценные уведомления Home Assistant

Ufanet Intercom передаёт подтверждённый входящий звонок в Home Assistant, не публикуя токенизированные provider URL preview/archive. Уведомление строится только на сущностях Home Assistant и защищённом соединении официального Companion App.

## Рекомендуемый blueprint

Импортируйте `blueprints/automation/ufanet_intercom/incoming_call_notification.yaml` и выберите:

- устройство домофона Ufanet;
- телефон с официальным Home Assistant Companion App;
- соответствующий сенсор **«Последний вызов»** (рекомендуется; используется как безопасный fallback при ручном тесте);
- соответствующую сущность **«Снимок последнего звонка»**;
- при необходимости соответствующую **live camera** домофона;
- при необходимости точную кнопку/реле **«Открыть дверь»**;
- URI панели Home Assistant для обычного открытия уведомления и fallback навигации;
- при необходимости имя Android notification channel.

Для совместимости blueprint сохраняет существующий device trigger `incoming_call`. Дополнительно интеграция создаёт нативную doorbell EventEntity, представляющую тот же подтверждённый звонок стандартным событием Home Assistant `ring`.

## Содержимое native push

Уведомление реального звонка строится только из безопасных данных Home Assistant. В заголовке указывается имя выбранного устройства домофона из device registry Home Assistant. В теле уведомления могут выводиться:

- адрес;
- подъезд;
- квартира;
- локальное время звонка.

Отсутствующие поля просто не выводятся. При ручном запуске используется тот же формат, но данные берутся из выбранного сенсора **«Последний вызов»**, а уведомление явно помечается как тестовое.

Время звонка преобразуется из подтверждённого `called_at` в локальный часовой пояс, настроенный в Home Assistant. Таким образом, в push не показывается provider UTC вместо локального времени HA.

## Последовательность доставки

1. Новый звонок подтверждается coordinator истории звонков — обычным polling либо обновлением, ускоренным FCM.
2. Blueprint **сразу** отправляет текстовый push. Создание изображения не задерживает первое уведомление.
3. Интеграция приватно загружает provider preview и извлекает JPEG в сущность **«Снимок последнего звонка»**.
4. Если изображение готово в пределах заданного окна, blueprint заменяет уведомление с тем же `tag` и URL `/api/image_proxy/image.entity_id`.
5. Исходный Ufanet `preview_url`/`archive_url` не попадает ни в переменные автоматизации, ни в push payload.

Для реального звонка используется стабильный `tag`, зависящий от выбранного HA-устройства домофона. Поэтому JPEG и последующие статусы обновляют одно уведомление, а новый звонок заменяет предыдущий незавершённый push этого домофона. Для ручного теста используется отдельный tag.

На Android первоначальный push использует `ttl: 0` и `priority: high`, чтобы уменьшить задержку доставки. Настраиваемый `channel` и `importance: high` относятся к Android; iOS игнорирует Android notification channel. Обновления картинки и статуса используют `alert_once: true`, чтобы не создавать намеренный повторный звуковой сигнал.

## Android и iOS actions

Blueprint использует inline actions Companion App, работающие на Android и iOS:

- **«Открыть дверь»** использует уникальный локальный Home Assistant action ID и не вызывает provider API напрямую;
- **«Открыть камеру»** использует стандартный action `URI`. Если выбрана live camera того же домофона, blueprint открывает More Info именно этой `camera.*` сущности через frontend-параметр `more-info-entity-id`. Если камера не выбрана или не принадлежит выбранному домофону, используется настроенный URI панели Home Assistant.

Одно устройство Ufanet может публиковать и live-, и archive-camera, поэтому в selector нужно явно выбрать live `camera.*`. Blueprint проверяет, что выбранная камера принадлежит тому же Home Assistant device, что и домофон, и тем самым исключает переход на постороннюю камеру.

Для кнопки открытия запрашивается аутентификация/разблокировка устройства там, где это поддерживается. В ходе live-теста Android выяснилось, что FCM data channel требует строковые значения action-полей, поэтому `authenticationRequired` передаётся как строка `"true"`, которую Android Companion преобразует в boolean. Apple-only поле `destructive` намеренно не включается в общий кроссплатформенный payload.

## Кнопки и модель безопасности

Если выбрана сущность **«Открыть дверь»**, уведомление от реального звонка содержит уникальный action ID, сформированный из context события Home Assistant. Provider UUID звонка в Companion payload не используется.

Кнопка открытия включается только тогда, когда выбранная button entity принадлежит тому же устройству Home Assistant, что и выбранный домофон Ufanet. Эта же проверка принадлежности повторяется непосредственно перед `button.press`, поэтому устаревшая или ошибочно выбранная сущность не может использоваться для открытия другого настроенного домофона.

Blueprint работает в режиме `restart`. Новый звонок отменяет предыдущий незавершённый запуск, инвалидирует listener старого action ID и заменяет текущее уведомление для этого домофона. Старый action ID новым запуском не принимается.

Кнопка **«Открыть дверь»** действует только в течение настроенного timeout. После отправки `button.press` либо после истечения timeout уведомление заменяется версией без кнопки открытия. Сообщение после нажатия намеренно говорит, что команда открытия **отправлена**, а не утверждает, что физическое состояние двери независимо подтверждено.

При ручном запуске физическая кнопка открытия намеренно отключена и используется отдельный notification tag. Поэтому **«Выполнить действия»** можно использовать для проверки push, не заменяя активное уведомление реального звонка и не создавая путь к открытию двери.

Открытие двери никогда не выполняется автоматически: требуется явный tap пользователя по action уведомления.

## Ручной тест

При ручном запуске настоящего `trigger.event` нет. Blueprint учитывает это и получает безопасные метаданные из выбранного сенсора **«Последний вызов»**, а само уведомление явно помечается как ручной тест. Он не ожидает полей `preview_url` или `archive_url` в event payload.

Это сделано намеренно: событие `ufanet_intercom_call` содержит только безопасные метаданные звонка и признаки `has_preview` / `has_archive`. Временные provider media URL остаются приватными runtime-данными интеграции.

## Live-проверка при разработке v0.31.0

Сценарий уведомлений был проверен на реальной установке Home Assistant с Android Companion App:

- ручная доставка уведомления с сохранённым снимком последнего звонка;
- synthetic `ufanet_intercom_call` через device trigger интеграции;
- доставка Android actionable notification;
- реальный входящий звонок Ufanet;
- наличие кнопки **«Открыть дверь»** при реальном звонке;
- успешный вызов выбранного Ufanet `button.press` из action уведомления.

Во время live-теста были найдены и исправлены две проблемы Android payload: обращение к несуществующему bare `context.id` заменено на context реального события, а специфичные значения action, которые FCM data channel требует строками, приведены к корректному строковому формату.

## Диагностика

Если при реальном звонке push не приходит:

1. Выполните blueprint вручную. Если тестовое уведомление пришло, доставка Companion работает; дальше нужно смотреть trace реального incoming-call trigger.
2. Если текстовый push приходит сразу, но изображение не появляется, проверьте сущность **«Снимок последнего звонка»** и диагностику Ufanet. Для JPEG нужен рабочий `ffmpeg` в среде Home Assistant.
3. Если уведомление приходит без кнопки открытия двери, проверьте, что выбрана сущность **«Открыть дверь»** того же устройства Ufanet и что запуск был вызван реальным звонком, а не вручную.
4. Если **«Открыть камеру»** только открывает панель Home Assistant, выберите соответствующую live `camera.*` в inputs blueprint. При несовпадающей камере blueprint намеренно использует fallback URI панели.
5. URL картинки должен иметь вид `/api/image_proxy/image.entity_id`; вручную добавлять `access_token` image entity не нужно.
6. При отказе Android push можно временно включить debug для `homeassistant.components.mobile_app.notify`. Ошибка FCM вида `data must only contain string values` указывает на некорректный actionable-notification payload, а не на Ufanet incoming-call trigger.

По умолчанию интеграция не использует critical/alarm-stream уведомления и намеренно не пытается обходить режим «Не беспокоить» на телефоне.
