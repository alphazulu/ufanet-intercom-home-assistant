# Ufanet Intercom 0.32.0 — draft release notes

> **RELEASE CANDIDATE / NOT PUBLISHED.** This document prepares the v0.32.0 release text. It does not authorize merge, tag or GitHub Release. Publication requires successful exact-head CI and separate explicit approval.

## Highlights

### Standalone UCAMS cameras

Ufanet accounts can contain UCAMS cameras that are not attached to an intercom. v0.32.0 discovers the paginated account inventory and exposes those cameras as separate Home Assistant devices while dynamically excluding the camera already represented by an intercom.

Each eligible standalone camera can provide:

- live HLS playback and JPEG snapshots;
- an archive camera with position, duration and navigation-step controls;
- previous, next and latest archive navigation buttons;
- a Motion EventEntity for cameras advertising `motion_alarm`;
- archive timeline motion markers;
- manual MP4 export and the existing export-library management workflow.

Discovery and entity creation recover from temporary provider failures. Cameras that disappear from a refresh become unavailable without deleting registry history, and newly discovered cameras can be added without reloading the ConfigEntry.

### Camera-only Lovelace UI

The existing `custom:ufanet-intercom-card` now recognizes a standalone-camera entity or device and routes archive/motion requests through dedicated backend services.

For standalone cameras the card retains only **LIVE** and **ARCHIVE**. Door opening, incoming calls, guests, authorized-device management, physical keys and intercom diagnostics are not offered because those capabilities belong to an intercom rather than a camera.

### Privacy boundary

The provider camera number is normalized into a stable opaque Home Assistant reference. It is used only inside authenticated UCAMS operations and is not returned through public response services, entity state/attributes, events or diagnostics.

The inventory normalizer discards media tokens, server domains and unknown fields. Motion uses an isolated private cursor store and publishes only normalized event times. Public test fixtures use synthetic identifiers.

## Live validation

The complete v0.32.0 feature path was exercised on Home Assistant on 2026-09-15 without reported issues:

- standalone devices appeared without duplicating the intercom camera;
- live HLS and JPEG snapshots opened;
- selecting an archive date/time moved playback to the requested position;
- archive navigation controls worked;
- the camera-only Lovelace UI showed the intended capabilities;
- motion handling and archive timeline behavior worked;
- MP4 export and export-library operations worked;
- Lovelace refreshes and a full Home Assistant restart preserved the expected devices and entities.

This evidence applies to the tested account. UCAMS remains a private provider API and is not claimed as a stable public contract.
