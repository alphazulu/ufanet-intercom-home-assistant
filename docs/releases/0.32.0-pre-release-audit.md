# Ufanet Intercom 0.32.0 — pre-release audit

**Status:** release candidate preparation in progress. No tag or GitHub Release has been created.

## Candidate scope

The candidate packages the standalone UCAMS camera implementation merged through PR #17:

- account-wide paginated private-camera inventory;
- standalone live and snapshot entities;
- archive entities, controls and navigation;
- privacy-safe archive playback/export/library services;
- isolated motion analytics and timeline markers;
- capability-driven standalone Lovelace UI;
- lifecycle recovery and restart persistence;
- expanded package and standalone coverage gates.

No door, guest, call, authorized-device or physical-key capability is added to standalone camera devices.

## Live evidence

The user completed the full Home Assistant acceptance checklist on 2026-09-15 and reported no issues. The check covered discovery/no intercom duplication, live video, JPEG, archive seeking/navigation, motion/timeline, MP4 export/library, Lovelace refresh behavior and a full Home Assistant restart.

## Privacy review

- Public Home Assistant identities use opaque deterministic camera references.
- Provider camera numbers remain internal to authenticated UCAMS calls.
- Inventory state does not retain media tokens or server domains.
- Public motion data is timestamp-only; provider IDs/raw rows remain private.
- Standalone motion cursor storage is isolated from intercom cursor storage.
- Current public test fixtures contain synthetic rather than account-specific camera/SKUD identifiers.
- No JWT, password, FCM credential, active guest token or tokenized media URL is intended to be present in the candidate tree.

Git history was not rewritten as part of release preparation. Existing release tags remain immutable.
