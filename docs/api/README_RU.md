# Неофициальная документация API Ufanet / UCAMS

[English version](README.md)

В этом каталоге документируются закрытые/недокументированные API, которые использует интеграция Ufanet Intercom для Home Assistant.

> Эти интерфейсы не являются публичным API-контрактом. Документация основана на тестах совместимости, наблюдаемом поведении официального мобильного приложения и reverse engineering. API может измениться без предупреждения.

## Статусы достоверности

Каждый endpoint или поведение должен иметь один из статусов:

- **Confirmed** — реально успешно проверено на существующей учётной записи/устройстве.
- **Observed** — наблюдалось в реальном ответе или коде приложения, но не проверялось исчерпывающе.
- **Inferred** — выведено из клиентского кода или окружающего поведения и требует дополнительной проверки.
- **Not supported** — конкретный вариант был проверен и в тестируемом виде не работает.

По мере новых тестов статус следует повышать до **Confirmed** только при наличии прямого подтверждения. Наличие production/validation-кода и зелёный CI сами по себе не повышают evidence label state-changing endpoint.

## Архитектура

Сейчас интеграция использует три уровня API:

1. **API аккаунта/домофона Ufanet** — `https://dom.ufanet.ru`
   - авторизация по договору и обновление токена;
   - поиск домофонов/SKUD и управление открытием двери;
   - история звонков;
   - гостевой и совместный доступ;
   - регистрация FCM и управление безопасностью авторизованных сессий;
   - capability/read-only физические ключи и validation-only enrollment/rename flow с privacy-safe Home Assistant surface.
2. **Управляющий API UCAMS** — `https://cloud.ucams.ru`
   - обмен JWT Ufanet на bearer-токен UCAMS;
   - получение метаданных камеры, live/archive токенов и медиасервера;
   - объявление analytics capabilities камеры и подтверждённый read-only отчёт `motion_alarm`.
3. **Медиасерверы UCAMS** — домены, которые возвращает UCAMS API
   - live HLS;
   - диапазоны и HLS видеоархива;
   - снимки и медиа звонков.

## Цепочка авторизации

```text
Договор/пароль Ufanet
        |
        v
Ufanet access + refresh JWT
        |
        | POST cloud.ucams.ru/api/v0/auth/
        v
UCAMS bearer token
        |
        +--> metadata камеры / analytics reports
        |
        v
метаданные камеры -> token_l / token_r -> медиасерверы
```

Критически важное различие:

- запросы к Ufanet используют `Authorization: JWT <access-token>`;
- запросы к управляющему API UCAMS используют `Authorization: Bearer <ucams-token>`.

## Как добавлять новые результаты тестов

Для каждого нового endpoint фиксируйте:

1. HTTP-метод и путь;
2. схему авторизации;
3. минимальный обезличенный запрос;
4. минимальный обезличенный ответ;
5. статус достоверности;
6. дату/условия теста, если это существенно;
7. побочные эффекты;
8. поля, семантика которых пока не ясна;
9. для write endpoint — отдельно факт принятия запроса и факт проверенного изменения состояния/read-back.

В одном изменении обновляйте и подробную страницу, и [STATUS_RU.md](STATUS_RU.md).

Никогда не добавляйте в репозиторий реальные пароли, JWT, refresh tokens, гостевые токены, URL с токенами, точные частные адреса, provider physical-key IDs/`external_id`, идентификаторы камер/событий из live-аккаунта, сырую историю событий и другие секреты конкретной учётной записи.
