# Безопасность

[English version](security.md)

Эти API управляют физическим домофоном и дают доступ к приватному видео/правам прохода, поэтому код следует считать security-sensitive.

## Секреты

Никогда не публикуйте и не логируйте:

- пароль Ufanet;
- Ufanet access JWT;
- Ufanet refresh JWT;
- bearer-токен UCAMS;
- `token_l` / `token_r`;
- гостевые/share токены;
- preview/archive/screenshot URL с токенами.

URL с медиатокеном является временным credential до истечения токена.

## Физические действия

Endpoint открытия двери выполняет реальное действие:

```text
/api/v0/skud/shared/<SKUD_ID>/open/?door=1
```

Приложения должны:

- требовать явное намерение пользователя;
- не выполнять автоматические повторы без очевидно продолжающегося пользовательского действия;
- не использовать endpoint как health check;
- разделять просмотр видео и управление доступом.

## Изменение гостевых прав

Создание, принятие и отзыв гостевого/shared доступа изменяет состояние авторизации. UI должен ясно обозначать такие операции и запрашивать подтверждение перед отзывом доступа.

## Диагностика и support bundles

Рекомендуемые правила редактирования:

- скрывать логин и пароль;
- никогда не выводить raw JWT/tokens;
- не включать точные частные адреса/номер квартиры без явной необходимости;
- удалять URL с токенами;
- по возможности заменять точный идентификатор камеры коротким необратимым hash;
- показывать наличие/expiry токена вместо его значения.

Интеграция Home Assistant следует этим принципам в скачиваемой диагностике.

## Примеры API

Все примеры должны использовать placeholders:

```text
<UFANET_ACCESS_JWT>
<UCAMS_JWT>
<CAMERA_NUMBER>
<SKUD_ID>
<CALL_UUID>
<TEMP_GUEST_TOKEN>
```

Нельзя «обезличивать» секрет заменой пары символов — значение нужно заменять полностью.

## Границы reverse engineering

Документация предназначена для совместимости с аккаунтами/устройствами, которыми разработчик вправе пользоваться. Она не предназначена для обхода авторизации, перебора чужих аккаунтов/устройств или доступа к чужому видео.
