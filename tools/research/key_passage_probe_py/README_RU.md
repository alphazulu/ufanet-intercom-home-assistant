# Read-only probe физических ключей и журнала проходов

Утилиты в этом каталоге проверяют наблюдавшиеся в официальном Android-клиенте read-only API-контракты физических ключей до/вместе с их использованием в интеграции Home Assistant.

## Обычный privacy-safe probe

`probe.py` выполняет только чтение:

1. получает список доступных функций аккаунта;
2. определяет домофоны с поддержкой записи ключей;
3. получает список физических ключей;
4. запрашивает до пяти последних проходов для каждого поддерживаемого домофона.

Probe **намеренно не выполняет** state-changing операции:

- `POST /api/v4/key/skud/<id>/auto_collect/enable/` (60-секундный enrollment);
- `POST /api/v4/key/edit/` (переименование);
- `POST /api/v4/key/skud/<id>/delete/key/` (удаление).

Эти контракты документируются отдельно в `docs/api/keys_RU.md`. Enrollment в validation-ветке Home Assistant должен проверяться только явным нажатием **«Добавить физический ключ»** с новым незарегистрированным ключом. Переименование и особенно destructive delete требуют отдельного controlled live-теста и не входят в этот read-only probe.

### Запуск обычного probe в Windows

Переключитесь на ветку, указанную в сообщении разработчика, затем выполните:

```cmd
cd tools\research\key_passage_probe_py
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python probe.py
```

Логин/договор и пароль запрашиваются интерактивно. Пароль при вводе не отображается. Вместо интерактивного ввода можно использовать локальные переменные окружения `UFANET_USERNAME` и `UFANET_PASSWORD`.

### Конфиденциальность обычного probe

`probe.py` намеренно не печатает:

- договор, пароль или JWT;
- ID домофона и адрес;
- `external_id` физического ключа;
- ID и имя ключа;
- устройства, связанные с ключом;
- точное время прохода;
- исходные JSON-ответы.

Вывод содержит только HTTP-статусы, количества, булевы признаки поддержки и названия подтверждённых полей схемы.

Для проверки достаточно прислать строки `[OK]`, `[RESULT]`, `[INFO]` и `[ERROR]`. Не присылайте переменные окружения, дамп трафика или исходные ответы сервера.

### Параметры обычного probe

```cmd
.venv\Scripts\python probe.py --page-size 5 --max-intercoms 10
```

- `--page-size` — от 1 до 25 записей для одного домофона;
- `--max-intercoms` — ограничение количества запросов истории;
- `--ufanet-base-url` — альтернативный сервер только для изолированных тестов.

## Raw inspector для визуального сравнения номера ключа

`raw_key_probe.py` — отдельный **read-only** диагностический inspector. Он предназначен именно для локального исследования реального ключа и намеренно печатает **все поля каждой записи**, которые Ufanet возвращает из:

```text
POST /api/v4/key/list/
```

Для каждого ключа он выводит:

- полный raw JSON item без нормализации;
- каждое поле отдельной строкой вместе с JSON-типом;
- UTC-подсказку для timestamp-подобных полей;
- для числовых и numeric-string полей — дополнительные decimal/hex представления, чтобы можно было глазами сравнить их с номером, нанесённым на физический ключ.

Inspector не выполняет enrollment, rename, delete, door-open и другие state-changing запросы.

### Запуск raw inspector

После установки зависимостей из этого же каталога:

```cmd
.venv\Scripts\python raw_key_probe.py
```

Если ключей несколько и нужен только конкретный item:

```cmd
.venv\Scripts\python raw_key_probe.py --key-index 1
```

Чтобы отключить дополнительные decimal/hex представления и оставить только raw поля:

```cmd
.venv\Scripts\python raw_key_probe.py --no-candidate-forms
```

### ВАЖНО: raw inspector выводит приватные идентификаторы

В отличие от `probe.py`, `raw_key_probe.py` **специально показывает** реальные access-control identifiers, включая внутренний provider `id`, `external_id`, `devices` и любые дополнительные поля, которые backend может добавить в key item.

Поэтому его вывод:

- не публикуйте в GitHub Issues/PR;
- не прикладывайте к публичным support bundles;
- не размещайте в публичных screenshots/logs;
- не добавляйте в документацию репозитория без полной ручной редактуры.

Сам скрипт credentials/JWT не печатает. Он показывает только данные ключевых item, полученные из read-only списка физических ключей.
